## What was shipped

### `tests/test_adversarial.py` — 9 tests, marker `adversarial` (9 / 9 PASS)
Replays the named Week-4 attack families against the real stack:
- **MemoryGraft** (directive embedded in tool output, `tool_derived`):
  poison never outranks the benign `user_stated` twin — asserted over 4
  paraphrased queries; `effective_score` monotonicity; corrigendum turn
  supersedes the poisoned row by slot key (`valid_until` closes it).
- **MINJA / MemoryTrap class** (newline-framed hijack text): stored
  verbatim, inert in context — `build_context` emits only `- <text>` data
  lines; the directive never escapes its quoted fact slot.
- **Influence over time** (threat model's own success language): low-
  importance poison selected by `decay_candidates`; after `decay()` it has
  zero presence in retrieval. + UUID-vs-str comparison fix in candidates.
- **Cross-tenant adversarial corpus** (EC-05 / Threat 1): near-identical
  wording, paraphrases, and token-colliding queries never surface the other
  tenant's rows; empty-tenant replay returns the explicit
  `no_relevant_memory` outcome.

## Bugs fixed this session
1. `replay_case` tenant mismatch: seeded under `case.user_id`, searched with
   synthetic tenant → both must be `case.user_id`.
2. `decay_candidates` returns UUID ids; producer returned str —
   `c["id"] == pid` never matched; compare `str(c["id"])`.
3. Relevance floor (min 2 shared lexemes): paraphrase-only queries raise
   `NoRelevantMemory`; re-worded replay queries to share tokens with the
   seed text (floor measures ranking, not availability).
4. Lambda arity `lambda r: HybridRetriever(store)` vs `lambda:` in bench.
